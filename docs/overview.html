EdgeGate · 基于嵌入式 Linux 的工业数据采集与边缘计算网关

0 外部依赖(核心栈) 11/11 单元测试通过 约 5,500 行源码 0 编译告警(-Wall -Wextra) 1 致命缺陷审稿发现并修复 WSL 实编译 + 真实 Mosquitto 演示验证

项目定位

工业现场 RS485/Modbus RTU 仪表数据采集 → 边缘实时处理(滤波、迟滞告警、数据质量)→ MQTT 上云 的完整网关实现。与"视频采集终端 / 语音助手 / 智能小车"等常见同类项目领域完全不同,但技术栈覆盖嵌入式 Linux 核心能力:系统编程、多线程、网络协议、串口通信、CMake 交叉编译、测试工程化。

总体架构

技术亮点

① Modbus RTU 主站协议栈(零依赖)

  • CRC16-Modbus 位运算实现(标准已知向量验证)
  • 功能码 03/04/06/0x10,异常应答分类,帧长奇偶性消歧
  • 3.5T 静默间隔切帧(审稿发现并修复"帧首锚点"致命缺陷)
  • 事务级互斥: 采集线程与命令线程不撕裂总线帧
  • 寄存器映射: 16/32 位组合、i16/u32/f32、scale/offset 标度

② MQTT 3.1.1 客户端(零依赖)

  • 报文编解码全量(含 CONNECT 标志位按 OASIS 规范)
  • QoS0/1 + 10s 未确认 DUP 重发;keepalive 心跳
  • PINGRESP 看门狗: broker 假死 1.5×keepalive 判死重连
  • 指数退避重连(1s→30s+抖动)+ clean session 订阅重建
  • 发送队列有界(512,断线丢旧保新)

③ 闭环验证与测试

  • openpty 创建真实虚拟串口对,termios/poll/字节流全真
  • 软件从站: 寄存器堆 + 5 种故障注入(演示 30 秒出效果)
  • 用自身编解码"自举"fake broker 测试 MQTT 客户端
  • 9600 波特逐字节流式回归测试(锁住 3.5T 切帧正确性)

④ 边缘计算与工程化

  • 滑动平均(O(1) 运行和)+ 迟滞告警状态机(防抖动,仅翻转上云)
  • 环形缓冲(双条件变量)、事件总线(快照后解锁回调)、状态机
  • 禁异常、RAII 线程/fd、优雅停止顺序(采集→遥测→MQTT→Cmd→从站)
  • JSON 配置、TCP 命令服务器(单线程 poll 多路复用)、CLI watch、可选 Qt GUI

审稿与修复记录

  • ▸ 致命: 从站 3.5T 切帧锚定帧首(真机必现半帧丢失)→ 改为最后字节锚点 + 流式回归测试
  • ▸ 高: MQTT 无 PINGRESP 看门狗 / 主站事务未串行化 / 状态机回调数据竞争 / 发送队列无上限 → 全部修复
  • ▸ 中: 命令服务器绑定回环 + 出站上限、串口超时预算、重连订阅去重、功能码 0x16→0x10 标准对齐 → 全部修复

交叉编译与部署(IMX6ULL)

步骤命令
交叉工具链apt install g++-arm-linux-gnueabihf(或 Linaro 工具链)
交叉构建cmake -S . -B build-arm -DCMAKE_TOOLCHAIN_FILE=cmake/toolchain-arm-linux-gnueabihf.cmake -DCMAKE_BUILD_TYPE=Release && cmake --build build-arm -j4
部署./scripts/deploy-arm.sh — scp 二进制 + 配置 + systemd 单元,ssh 安装启动
真机配置config/edge-gate-arm.json: serial.device=/dev/ttymxc2、slaveSim=false、mqtt.host 指向服务器
